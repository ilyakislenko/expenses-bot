# Отложенные идеи

Записано, чтобы не потерять. Порядок — по важности.

## Чек из налоговой по QR

Бот уже читает QR кассового чека (`src/services/receipt/qr.js`): точные итог, дата и время. Строк покупок в QR нет —
их отдаёт ФНС. Варианты:

1. **Официальный программный доступ ФНС** (`openapi.nalog.ru:8090`, «мастер-токен» по техническим условиям:
   https://www.nalog.ru/files/kkt/pdf/Технические%20условия%20использования.pdf; пример клиента —
   https://github.com/QortexDevs/fnsapi). По QR (t, s, fn, i, fp, n) возвращает полный чек со строками — телефон не
   нужен. **Проверить:** кому выдают токен (физлицо / самозанятый / ИП / юрлицо), лимиты запросов, условия.
2. Вход в «Проверку чеков» по номеру телефона владельца — один вход на всех (все чеки пользователей окажутся в
   кабинете владельца; неофициально, лимиты и блокировки).
3. Каждый пользователь входит своим номером (кнопка «Подключить налоговую») — приватнее, но лишний шаг и хранение
   входа пользователя.
4. Платный посредник (proverkacheka.com) — просто, но платно.

Если строки из ФНС получены — они точнее модели: модель для таких чеков не нужна. При ошибке ФНС — как сейчас.
