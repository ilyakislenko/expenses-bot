# Страницы и функции Telegram бота для учета расходов

## Главная reply-клавиатура

```
[📊 Обзор месяца] [📅 Сегодня]
[💵 Доходы]       [🔁 Регулярные траты]
[💰 Добавить семейную трату] [☰ Ещё]   ← кнопка-исключение только у премиума с семьёй
```

Кнопка-исключение зависит от режима «все траты в семью» (`users.family_mode`): выключен — «💰 Добавить семейную
трату» (следующая трата в семью), включён — «👤 Личная трата» (следующая трата личная, состояние
`adding_personal_expense`).

Всё редкое — в inline-меню «☰ Ещё»: семья, подписка, экспорт CSV, импорт выписки, настройки, справка (+ админка для админов).

Кнопки старой клавиатуры (`LEGACY_MENU_BUTTON_KEYS` в `utils/constants.js`) распознаются: бот присылает новую
клавиатуру и открывает ближайший раздел. Нажатие на кнопку из старого сообщения, для которой нет обработчика,
показывает alert `button_outdated`.

## Ввод

| Сообщение | Что происходит |
|-----------|----------------|
| `250 кофе`, `20 USD такси`, `300`, `12,5€ латте` | Трата. Валюта — код или символ сразу после суммы, иначе основная валюта |
| `+50000 зарплата`, `+1000 USD фриланс`, `+300$` | Доход. Без кода — валюта дохода пользователя (`users.income_currency`) |
| Фото чека (или картинка файлом) | Каждая позиция чека — отдельная трата сразу, затем список чека для правки (см. «Фото чека») |

Сумма — от 0.01 до 99 999 999 (предел колонки), пробел может разделять тысячи: `1 000 кофе`, `15 000,50 €`.
Категория траты запоминается по описанию (без учёта регистра): если такая трата уже была в доступной категории,
запись создаётся сразу, иначе показывается выбор категории (`category|<id>`). Черновик привязан к сообщению с выбором:
кнопки другого сообщения его не записывают, «Отмена» удаляет его, а кнопка карточки без черновика (отменён или бот
перезапущен) отвечает alert «черновик устарел, отправь трату ещё раз». Повторное нажатие на ту же карточку трату не дублирует.
После записи приходит карточка с кнопками «↩️ Отменить», «🏷 Категория», «✏️ Изменить» и для премиума с семьёй — «В семью / Из семьи».

## Премиум, подписка и воронка

- **Записи без лимита** для всех. Премиум даёт: бюджеты, полные итоги периода, 160 символов в описании,
  до 5 своих категорий, семейный бюджет, изменение суммы/описания записи (`USER_LIMITS` в `utils/constants.js`).
- **Пробный период** — 14 дней при первой регистрации. Право на него забирается атомарно
  (`UPDATE users SET has_trial = FALSE … RETURNING`), поэтому параллельные `/start` дают один пробный период;
  «новый пользователь» определяется по результату INSERT, дубль первого `/start` из той же пачки молчит.
- **Тарифы** (`PREMIUM_TARIFFS`): месячный продаётся как подписка Telegram Stars с автопродлением
  (`createInvoiceLink` с `subscription_period=2592000`, кнопка помечена 🔁), 3/6/12 месяцев — разовые.
  Скидка и зачёркнутая цена считаются от помесячной оплаты (`tariffDiscount`: месячный тариф × число месяцев;
  сейчас 22% / 33% / 44%); строка «≈ … в месяц» — только у многомесячных тарифов.
  Каждое продление приходит как `successful_payment` с `is_recurring` и продлевает премиум на 30 дней;
  повторная доставка того же `telegram_payment_charge_id` игнорируется. Пока подписка оплачена
  (`premium_transactions.is_recurring`, `subscription_expires_at`), месячный тариф повторно не предлагается.
  Отмена — у пользователя в Telegram: Настройки → Мои звёзды. Когда админ снимает премиум, действующая подписка
  Stars тоже отменяется (`PaymentService.cancelActiveSubscription`).
- **Перед оплатой** (`pre_checkout_query`, `PaymentService.checkPreCheckout`): валюта XTR и сумма, равная текущей
  цене тарифа из payload, иначе `payment_outdated` (ссылки на оплату не истекают — старая цена не пройдёт);
  платит тот, для кого создана ссылка (`payload.user_id`), иначе `payment_foreign_payer`; вторая месячная подписка
  при действующей отклоняется с `payment_subscription_already_active`.
- **Возврат** (`PaymentService.revokeRefundedPayment`): админка → пользователь → «Найти транзакцию по хэшу» → «Вернуть»
  вызывает `refundStarPayment`; затем у транзакции статус `refunded`, из даты окончания премиума вычитается срок покупки,
  а если платёж был по подписке — подписка отменяется (`editUserStarSubscription`). То же делает обработчик
  `refunded_payment` (возврат не из админки); повторное уведомление о том же платеже ничего не меняет.
  Поиск по хэшу находит и пожертвования: их возврат ставит `donations.status = 'refunded'`.
- **Даты премиума** (`users.premium_expires_at`, `premium_activated_at`) — `TIMESTAMP` без пояса во времени процесса
  Node: в SQL их сравнивают с временем из Node (параметр), а не с `NOW()`. Флаг `users.premium` у истёкших снимает
  cron каждые 10 минут (`disableAllExpiredPremium`).
- **Уведомления об окончании** (`PremiumLifecycleService`, cron в :25 каждого часа, только 10:00–20:59 по местному
  времени, по одному разу на срок — `user_notifications`): за 2 дня до конца, в первые сутки после и через 7 дней.
  Тексты — по источнику премиума: пробный, выданный админом, оплаченный. Пользователи с действующей подпиской
  с автопродлением их не получают, как и те, у кого возврат денег был в последние 2 дня срока или снял премиум.
- **Напоминания** новым пользователям включены по умолчанию (`users.reminder_enabled DEFAULT TRUE`).
- **Источник** — код из ссылки `https://t.me/<бот>?start=<код>` (латиница, цифры, `_`, `-`, до 64 символов),
  сохраняется в `users.source` при первом `/start`.
- **Воронка** (`user_funnel_events`, первое наступление шага): `registered` → `onboarding_completed` → `first_expense` →
  `paywall_viewed` (экран подписки) → `tariffs_viewed` → `paid`. Отчёт: админка → «📈 Воронка» (`panel_funnel_30|90|0`),
  по источникам, плюс «вернулись через неделю» — ручная трата спустя 7+ дней после регистрации.

## Команды

| Команда | Описание |
|---------|----------|
| `/start` | Для нового пользователя — онбординг (язык → валюта → часовой пояс), затем приветствие; для вернувшегося — короткое сообщение и клавиатура. `/start <код>` — вход по рекламной ссылке. Стартовый язык экрана — язык Telegram (`ja` → `jp`, `kk` → `kz`, `pt-br` → `pt`), иначе en. Шаг онбординга хранится в callback_data (`set_language\|ru\|ob`, `set_currency\|RUB\|ob`, `time\|h\|m\|ob`) и переживает рестарт; «Назад» ведёт на предыдущий шаг (`ob_language`, `ob_currency`), на шаге языка его нет |
| `/stats`, `/total`, `/categories` | Обзор текущего периода |
| `/history` | Записи за сегодня |
| `/income` | Доходы за период |
| `/recurring` | Регулярные траты |
| `/savings` | Накопления, цели и прогноз |
| `/export` | Экспорт CSV: выбор периода и фильтр по категориям |
| `/import` | Импорт банковской выписки: форматы и как выгрузить (как «📥 Импорт выписки» в «☰ Ещё») |
| `/undo` | Удалить последнюю запись |
| `/settings`, `/currency`, `/timezone` | Настройки |
| `/family` | Семейный бюджет |
| `/limits` | Подписка и лимиты |
| `/menu` | «☰ Ещё» |
| `/help` | Короткая справка |
| `/cancel` | Отменить любой ожидаемый ввод (правка записи, черновик траты, доход, бюджет, регулярная трата и т.д.) |
| `/paysupport`, `/terms`, `/privacy`, `/refund` | Требования Telegram Payments. Ссылки — из `.env` (`TERMS_URL`, `PRIVACY_URL`, `REFUND_POLICY_URL`, `SUPPORT_EMAIL`); тексты документов — `docs/terms.md`, `docs/privacy.md`, `docs/refund.md` (на GitHub: telegra.ph в России заблокирован) |

Описание бота до `/start`, короткое описание и меню команд на всех 13 языках задаёт `node scripts/set-bot-profile.js`
(тексты — ключи `bot_description`, `bot_short_description`, `command_*` в `src/locales`). При старте бот их не меняет;
после правки текстов или списка команд скрипт нужно запустить заново.

## Навигация

Переходы по inline-кнопкам редактируют текущее сообщение (`utils/respond.js`), новое сообщение отправляется только
в ответ на ввод текста или команду.

### Обзор, день, карточка записи

| Callback | Описание |
|----------|----------|
| `ov\|<offset>` | Обзор пользовательского периода (`period_start_day`): расходы, доход, остаток, категории, ближайшие регулярные. `offset` 0 — текущий, -1 — предыдущий… В текущем периоде у премиума — шкала общего бюджета и «🎯 лимит N» у категорий с бюджетом (⚠️ от 80%, 🚨 при превышении). Подсказка про доходы — только первые 14 дней после регистрации |
| `rp\|<offset>` | Итоги периода (`ReportService.buildReport`) |
| `oc\|<categoryId>\|<offset>\|<page>` | Записи категории за период (по 10 на страницу) |
| `dy\|<offset>\|<page>` | Записи за день (0 — сегодня, -1 — вчера…) |
| `fd\|<page>` | Семейные записи за сегодня |
| `ex\|<id>\|<back>` | Карточка записи |
| `xd\|<id>\|<back>` | Удалить запись (для свежей — «Отменить») |
| `xc\|<id>\|<back>` → `xs\|<id>\|<categoryId>\|<back>` | Сменить категорию |
| `xe\|<id>` | Изменить сумму/описание следующим сообщением (бесплатно) |
| `xf\|<id>\|<back>` / `xu\|<id>\|<back>` | Перенести в семейный бюджет / убрать из него (премиум) |
| `noop` | Номер страницы в пагинации |

`<back>` — экран, куда возвращается карточка: `d.<offset>.<page>`, `c.<categoryId>.<offset>.<page>`, `f.<page>`,
`r.<receiptId>.<page>` (список чека) или `n` (свежее подтверждение без кнопки «Назад»). Шаблон — `BACK_VIEW_PATTERN`
в `handlers/ExpenseHandlers.js`; экраны других разделов подключаются через `registerBackView` (`r` — `ReceiptHandlers`).

### Доходы

| Callback | Описание |
|----------|----------|
| `income_menu` | Доходы за текущий период: нумерованный список, итог в основной валюте, остаток |
| `in\|<id>` | Карточка дохода |
| `income_delete\|<id>` | Удалить доход из карточки |
| `ie\|<id>` | Изменить доход (бесплатно, как у трат; кнопка в карточке и после записи). Состояние `editing_income:<id>`: `60000` — только сумма, `60000 USD аванс` — сумма, валюта и описание, текст без числа — только описание |
| `income_undo\|<id>` | Отменить только что записанный доход |
| `income_add` | Ввод дохода (состояние `adding_income`) |
| `income_currency` / `change_income_currency` | Выбор валюты дохода (из меню доходов / из настроек валют) |
| `set_income_currency\|CUR\|origin` | Установка валюты дохода (`origin`: `income` / `settings`) |

Нижние кнопки главной клавиатуры сбрасывают незавершённый текстовый ввод (доход, правка записи и т.п.), чтобы
следующее сообщение не ушло в брошенный ввод; черновики на карточках выбора категории остаются.

### Регулярные траты

| Callback | Описание |
|----------|----------|
| `recurring_menu` | Нумерованный список, даты следующей записи, итог в месяц |
| `rc\|<id>` | Карточка регулярной траты |
| `recurring_add` | Создание: сумма и описание (`adding_recurring`) → число месяца (`adding_recurring_day`) → категория |
| `recurring_category\|<id>` | Выбор категории и сохранение |
| `recurring_delete\|<id>` | Удаление (уже записанные траты остаются) |

Cron каждые 15 минут записывает трату в расходы, когда в локальном дне пользователя наступает число списания
(в коротких месяцах — последний день). За месяц — не более одной записи (`recurring_expenses.last_charged_month`),
пропущенные месяцы задним числом не досписываются. Если при создании число в текущем месяце уже прошло —
первая запись в следующем месяце; если оно сегодня — запись сразу. Лимит записей (`MAX_NOTES_COUNT`) действует и здесь:
при достижении лимита трата за месяц пропускается, пользователь получает уведомление.
Авто-записи (`expenses.recurring_expense_id`) не считаются ручными записями для напоминалок.

### Бюджеты (премиум)

| Callback | Описание |
|----------|----------|
| `bg_menu` | Бюджеты на текущий период: потрачено / лимит, шкала, остаток или перерасход. Без премиума — описание и кнопка премиума |
| `bg\|<id>` | Карточка бюджета: изменить сумму, удалить |
| `bg_cat` | Выбор категории для нового бюджета |
| `bg_add\|<total\|categoryId>` | Ввод лимита следующим сообщением (состояние `setting_budget:<цель>`), `10000` или `150 USD`; существующий бюджет перезаписывается |
| `bg_del\|<id>` | Удалить бюджет |

Бюджет (`category_budgets`) — лимит на пользовательский период, общий (`category_name IS NULL`) или на категорию
(по имени, как группирует обзор). Траты и лимит пересчитываются в основную валюту по текущему курсу.
После записи траты (ручной, смены категории, регулярной) `BudgetService.checkAfterExpense` проверяет бюджет категории
и общий: на 80% и при превышении приходит предупреждение, каждое по разу за период (`user_notifications`
`budget_80` / `budget_100`, ключ `<id бюджета>:<начало периода>:<лимит>`); после превышения 80% уже не присылается,
после изменения лимита предупреждения по новому лимиту приходят заново. Бюджет привязан к имени категории: при
переименовании своей категории переходит на новое имя, при удалении — удаляется (`CategoryService`).

### Накопления

Отдельный раздел в «☰ Ещё» (`sv`, `/savings`), ежедневный ввод не трогает. Бесплатно: накопления, счета (до 10),
долги (до 10) и прогноз; цели — 1 бесплатно, до 10 с премиумом (`USER_LIMITS.*.MAX_SAVINGS_GOALS`, уже созданные цели
после окончания премиума остаются).

| Callback | Описание |
|----------|----------|
| `sv` | Главный экран. Текст: `🏦 *Накопления — {всего}*`, при долгах — `💳 Долги — X · капитал Y` (капитал = накопления − долги); секции (только непустые) *Счета* (`иконка название — сумма ≈ в основной · ставка%`, пустая общая копилка при других счетах скрыта), *Цели* (шкала, %, ≈ срок или ✅), *Долги* (сумма · ставка · до ММ.ГГГГ); последняя строка — `📈 Через год ≈ 1,53 млн ₽ (откладываешь ~X/мес)` или «пока не знаю» + кнопка `svm\|s`. Кнопки: «🔄 Обновить остатки» (`svu`), копилки по 2 в ряд (счета → цели → долги) с компактной суммой/процентом, «➕ Добавить» (`svn`) · «📈 Прогноз» · «⚙️ Настройки», «⬅️ Назад». Пустое состояние: короткое вступление, «✏️ Указать сумму накоплений» (`svs\|<общая>`), «➕ Добавить счёт» (`sva`) |
| `svn` | Что добавить: «💼 Счёт» (`sva`) · «🎯 Цель» (`svgn`) · «💳 Долг» (`svbn`) |
| `svu` → `svuk\|<id>` / `svux` | Мастер «Обновить остатки»: по очереди общая копилка (если в ней что-то есть или других счетов нет), счета, цели со своей копилкой, долги — `{иконка} {название} (i/n) — сейчас X. Сколько теперь?` (`sv_in:upd:<id>`; ввод — новая сумма, `0` можно, другая валюта пересчитывается) / «✅ Без изменений» / «⏹ Хватит». Очередь — в памяти процесса (`UpdateWizards`, 30 мин), кнопка старого шага или протухший мастер → «неактуально» и главный экран. Итог сверху главного экрана: «Готово: накопления A → B (±Δ)», при долгах — «Капитал: A → B», поздравления с целями |
| `svp\|<id>` | Карточка счёта/общей копилки: `{иконка} *название* — сумма (≈ в основной)`, ставка («Без процентов» / «16% годовых» / «Ставка как в настройках (X%)») · «обновлено дд.мм» (последнее изменение или создание), последние 3 изменения. Кнопки: «✏️ Новая сумма» (`svs`), «➕ Пополнить» · «➖ Снять» · «🔄 Перевести» (если есть куда и что), «⚙️ Настроить» (`svpc`). Для цели — карточка цели, для долга — карточка долга |
| `svpc\|<id>` | Настройки счёта: «✏️ Название» (`svpn`), «📈 Ставка» (`svpy`), «🗑 Удалить» (`svpx`, не для общей копилки), «⬅️ К счёту» |
| `sva` | Новый счёт: «Как назвать счёт?» (`sv_in:acc`). Если в строке уже есть валюта или `N%` (`Вклад USD 4%`, `Крипта USDT`) — сразу сумма; иначе счёт создаётся в основной валюте и бот спрашивает валюту кнопками (`svac\|<id>\|<код>`: основная, USD, EUR/RUB; «🌐 Другая» — `svaco\|<id>`, все поддерживаемые) или текстом (`sv_in:accur:<id>`: `USD`, а `3000 USD` — сразу сумма); затем сумма (`sv_in:set:<id>`). Валюту можно сменить, только пока счёт пуст. До 10 счетов бесплатно |
| `svpy\|<id>` / `svpyd\|<id>` | Своя ставка счёта (`0` — без процентов; `sv_in:pyield:<id>`) / «как в настройках» (NULL) |
| `svpn\|<id>` | Название счёта, в том числе общей копилки (`sv_in:name:<id>`) |
| `svpx\|<id>` → `svpxc\|<id>` | Удаление счёта (не общей копилки); деньги переходят в общие накопления по курсу |

Компактные суммы (`utils/savingsView.js`, `compactAmount`) — на кнопках, в строке «через год» и в прогнозе: от
1 000 000 — `1,53 млн ₽`, от 10 000 — `241 тыс ₽`, меньше — целые; слова — ключи `savings_compact_thousand|million`,
десятичная точка у en/hi/jp/zh, у остальных запятая (как в CSV). В карточках — точные суммы. Иконка счёта
(`potIcon`) по названию: налич/cash 💵, вклад/депозит/накопит/deposit/saving 🏦, крипт/crypto/btc/usdt/eth 🪙,
скин/steam/skin 🎮, брокер/акци/инвест/broker/stock/invest 📈, иначе 💼; общая копилка 💰, цели 🎯, долги 💳.

Модель (`savings_pots`): общая копилка (`kind = 'general'`) — счёт по умолчанию, одна на пользователя (создаётся при
первом заходе в основной валюте, не удаляется; без названия — «Общие накопления»); счета — `kind = 'account'`, своя
валюта и `yield_rate`; цели — `kind = 'goal'`. Цель `own` — своя копилка с балансом; `total` — без своих денег,
прогресс от всех накоплений. Всего = общая + счета + цели `own`, в основной валюте по курсу. Крипту и скины бот не
оценивает — их стоимость указывают в валюте (USD) и обновляют «новой суммой» или мастером «Обновить остатки».
Долги — `kind = 'debt'`: `balance` — сколько осталось вернуть, `currency`, `yield_rate` — ставка по долгу (NULL —
без процентов), `monthly_payment` — плановый платёж в месяц (NULL — не задан). Долги не накопления: не входят во
«всего», прогноз накоплений, цели «от всех накоплений» и переводы (`svt`/`svtt` и `svd`/`svw`/`svs` их не принимают,
`SavingsRepository.changeBalance(..., debt)` разделяет долги и копилки). Капитал = всего − долги в основной валюте по
курсу.

Прогноз (`utils/savingsForecast.js`) помесячно: каждый счёт растёт по своей ставке (`yield_rate`; NULL — ставка из
параметров), новые взносы и деньги целей — по ставке из параметров; проценты — `ставка/12` с ежемесячной капитализацией, взнос в конце месяца,
рост взноса раз в год, «в сегодняшних деньгах» — деление на `(1 + инфляция)^(месяцы/12)`, баланс не ниже нуля. Взнос
«авто» (`SavingsService.autoMonthly`) — среднее «доходы − траты» за последние 3 полных периода, в которых записан хотя
бы один доход; таких нет — взнос неизвестен (прогноз просит записать доходы или задать взнос). Для цели: срок достижения
при текущем взносе (для `own` — как будто весь взнос идёт в неё), с инфляцией — цель дорожает; при сроке — нужный взнос
в месяц на число полных месяцев до срока. Достижение поздравляется один раз (`achieved_at`, сбрасывается, если сумма
снова ниже цели).

Погашение долга (`utils/debtForecast.js`): каждый месяц начисляется `остаток · ставка/12`, затем вносится платёж
(последний — сколько осталось); платёж ≤ процентов — долг не гасится; дольше 50 лет — «дольше 50 лет». В прогнозе
долг идёт по плановому платежу, без платежа растёт на проценты; платежи по долгам считаются частью обычных трат (они
уже в «доходы − траты»), поэтому взнос в накопления не уменьшают.

### Итоги периода

Все: расходы, сравнение с прошлым периодом, доход и остаток, топ-3 категорий и описание полной версии.
Текущий период называется «Итоги на сегодня». Премиум: каждая категория со шкалой и изменением к прошлому периоду
(если в прошлом периоде были траты), категории без трат, бюджеты (заведённые
не позже последнего дня периода), средняя трата в день (для текущего периода — по прошедшим дням), самая крупная трата.
Cron в :35 каждого часа: в первые 3 дня нового периода, 10:00–20:59 по местному времени, присылает итоги прошлого
периода пользователям с ручными тратами за 45 дней — по разу за период (`user_notifications` `period_report`),
только если в прошлом периоде были траты.

### Ежедневная сводка

Бесплатно, выключена по умолчанию (`users.daily_summary_enabled`). Настраивается на экране напоминаний.
Cron в :00 каждого часа: если локальный час пользователя равен `users.daily_summary_hour` (NULL — 21), присылает
сводку за сегодня — дата, расходы в основной валюте и число записей, доход за день (если был), топ-3 категорий,
кнопка «📅 Сегодня» (`dy|0|0`). По разу за локальный день (`user_notifications` `daily_summary`, ключ — дата);
в дни без трат не приходит (пустые дни закрывают напоминания).

### Сводка недели

Бесплатно, выключена по умолчанию (`users.weekly_insight_enabled`). Настраивается на экране напоминаний: вкл/выкл
(`toggle_weekly_insight`) и «👀 Показать сейчас» (`weekly_insight_now` — присылает сводку отдельным сообщением, даже
если она выключена; без трат за 5 недель — alert). Cron в :00 каждого часа: по понедельникам в 10:00 по местному
времени, по разу за локальную неделю (`user_notifications` `weekly_insight`, ключ — дата понедельника), только если
за последние 5 полных недель были траты (`WeeklyInsightService`). Суммы — в основной валюте, как в обзоре
(свои траты, в том числе перенесённые в семью):

- прошлая неделя (пн–вс по местному времени) против среднего за 4 недели до неё; история считается от самой старой
  недели с тратами, меньше 2 недель — «истории пока мало»; изменение меньше 5% — «как обычно»;
- топ-3 категорий недели с изменением к их среднему, категория с наибольшим ростом и с наибольшим снижением в деньгах
  (от 10% её среднего; новая категория — рост);
- текущий период (`period_start_day`): потрачено, прогноз на конец при текущем темпе (с 3-го дня периода) против
  прошлого периода и общего бюджета (`category_budgets`, если задан), доход − расходы (если в периоде есть доходы).

Кнопки под сводкой: «📊 Обзор» (`ov|0`) и «🔕 Выключить сводку недели» (`weekly_insight_off` — выключает, у сводки
остаётся только «Обзор»).

### Семья

Премиум. Один человек — одна семья (`family_user.user_id` уникален): создать семью или принять приглашение,
уже состоя в семье, нельзя (`family_already_member`).

- **Приглашение** (`family_invite`, ввод username): поиск без учёта регистра; если username совпал у нескольких
  записей — «пользователь не найден». Username и имя обновляются из `ctx.from` при каждом апдейте
  (`profileRefreshMiddleware`, запись в БД только при изменении); у прежнего владельца username сбрасывается.
  Приглашённый должен иметь действующий премиум (`isPremiumUser`). Приглашение живёт 24 часа; у человека одно
  ожидающее приглашение. Просроченные переводятся в `expired` перед созданием и показом приглашений, а также при
  попытке принять просроченное, — просроченное приглашение не мешает пригласить человека снова.
- **Участники** (`family_members`): дата вступления — в языке и часовом поясе владельца. Исключить можно только
  участника своей семьи и не себя (`remove_member|<id>` → `confirm_remove_member|<id>`).
- **Выход и исключение**: траты участника в этой семье становятся его личными (`family_id = NULL`) — бывшая семья
  их больше не видит; об этом говорят подтверждение исключения, сообщение о выходе и уведомление исключённому.
- **Удаление семьи** (владелец): все семейные траты становятся личными у их авторов.
- **Все траты в семью** (`family_mode_toggle`, первая кнопка меню семьи): обычный ввод траты записывается в семью,
  пока у пользователя есть премиум и семья; иначе режим не действует (флаг сохраняется). Переключение
  обновляет меню и присылает reply-клавиатуру с новой кнопкой-исключением. Отдельную запись можно перенести
  кнопками карточки «В семью» / «Из семейного бюджета».

### Админка

- Массовое уведомление (`panel_broadcast`) и его превью отправляются простым текстом, без разметки: текст уходит как есть.
- Баг-репорты (`panel_bug_reports`): статистика и последние новые; «Все репорты» (`panel_all_bug_reports`) и «Новые»
  (`panel_new_bug_reports`) — последние 10, текст до 300 символов, простым текстом.
- Поиск пользователя: по id или username (без учёта регистра, все совпадения).

### Импорт банковской выписки

Бесплатно. «☰ Ещё» → «📥 Импорт выписки» (`import`) или `/import` — экран с форматами; сам файл можно прислать
в любой момент без состояния (`bot.on('document')`): `.csv`, `.pdf`, `.txt` (или такой MIME без расширения), до 20 МБ
и 5000 операций. Другие файлы — подсказка `import_unsupported_file`. Лимит `import` в `securityMiddleware` — 10 файлов за 10 минут.
Файл скачивается (`getFileLink`), разбирается в памяти и не сохраняется.

Формат определяется по содержимому (`utils/statement`):
- **Т-Банк CSV** — по набору столбцов (`Дата операции`, `Статус`, `Сумма платежа`…), `;`, часто windows-1251
  (не UTF-8 → cp1251). Сумма и валюта платежа (валюта счёта), сумма операции — для сверки с ручными записями; `FAILED` пропускается.
- **Любой CSV** — разделитель `;` `,` таб `|`, строка заголовков в первых 30 строках; столбцы по словам (ru/en и подписи
  экспорта бота на всех языках): дата, сумма или расход/приход, валюта, описание, категория, статус, MCC, тип. Даты
  `dd.mm.yyyy`, `dd.mm.yy`, `yyyy-mm-dd`, `dd/mm/yyyy`, `mm/dd/yyyy` (если по столбцу видно, что первое число — месяц),
  со временем или без (тогда 12:00). Знак суммы: минус — трата; нет ни одной отрицательной суммы и нет типа — всё траты
  (так читается и экспорт самого бота). Нет даты и суммы — `import_csv_columns`.
- **Сбер PDF** — строка `дд.мм.гггг чч:мм [код] Категория сумма [остаток]` (`+` — поступление), ниже дата обработки, код
  и описание; склеиваются разорванные строки и перенос категории, колонтитулы пропускаются. Валюта — RUB.
- **Kaspi Gold PDF** — `дд.мм.гг ± сумма ₸ Тип Детали` (Покупки, Переводы, Пополнения, Снятия, Разное). Валюта — KZT.
- Текст PDF собирается по координатам (`pdfText.js`, `pdf-parse`). PDF с паролем, скан — `import_pdf_error`.

Валюта не из списка бота — операция пропускается (счётчик). Переводы — категория/тип банка «перевод», «пополнение»,
«снятие», «наличные»… или описание, начинающееся с «Перевод», «Пополнение»…

| Callback | Описание |
|----------|----------|
| `import` | Экран импорта: форматы и как выгрузить |
| `imx\|1` / `imx\|0` | Учесть / пропустить переводы (вопрос появляется, только если они есть; потом кнопка переключает выбор) |
| `imgo` | Записать |
| `imno` | Отмена превью — ничего не записано |
| `imu\|<id>` | Отменить импорт: удаляет ровно записи этой партии (`imports.id`); повторно — alert «уже отменён» |

Превью (ничего не записано): период, траты и доходы (без переводов) — число и суммы по валютам, топ-3 категорий
(в основной валюте), переводы (число, списания/поступления), что будет пропущено. Разобранная выписка хранится в памяти
`ImportService` по id сообщения превью 30 минут (до 5 на пользователя); после рестарта или записи кнопки отвечают
alert `import_outdated`, двойное нажатие «Импортировать» записывает один раз.

Запись (`ImportRepository.createImport`) — одна транзакция: партия `imports`, личные траты (`family_id` NULL) и доходы
пачками с исходной датой (локальное время выписки → `created_at_utc` по поясу пользователя), `import_id` и `import_hash`.
Бюджеты не проверяются. Категория траты: последняя категория трат с таким описанием (если доступна), затем категория банка /
MCC / известные магазины → системная категория (`utils/statement/categories.js`), иначе «Другое». Траты из импорта
не участвуют в запоминании категории для ручного ввода (`getLastCategoryIdForDescription`).

Дубликаты: `import_hash` — sha256 (вид, дата, сумма, валюта, описание без учёта регистра, номер среди одинаковых операций
файла), уникален на пользователя — повторный импорт того же файла ничего не добавляет. Операция, совпавшая с записью не
из импорта (та же сумма и валюта, или сумма операции в валюте покупки, в тот же локальный день), пропускается как «уже
записано вручную»; одна запись закрывает одну операцию.

### Фото чека

Любое фото в личном чате (самый крупный размер не больше 1,5 МБ; Telegram сжимает фото до ~1280px и присылает пиксели
уже повёрнутыми) или картинка файлом (jpg/png/webp; HEIC — только если все слоты Gemini). Файл больше 1,5 МБ или JPEG
с поворотом в EXIF (Orientation ≠ 1, обычно фото iPhone файлом — модели EXIF не учитывают и видят чек боком,
`receipt/image.js`) — «пришли как фото». Состояние не нужно.

Порядок: проверки (настроено ли, лимит, размер), один чек за раз на пользователя (второе фото, пока идёт первое, —
«подожди, ещё распознаю прошлый чек»), скачивание, «🔍 Распознаю чек…» — и обработчик апдейта сразу возвращается:
распознавание идёт в фоне (локальной модели нужна минута-две — иначе polling задержал бы остальных, а Telegraf оборвал бы
обработчик через 90 с), каждые 4 с уходит `typing`, затем сообщение превращается в результат или текст ошибки.
Если чек распознаёт локальный слот — «это может занять 1–2 минуты»; если слот занят — «ты в очереди: N».
При перезапуске бота незаконченное распознавание теряется (в лимит не засчитывается).

Распознаёт цепочка бесплатных нейросетей (`services/receipt/chain.js`): слоты `RECEIPT_AI_1_*`, `RECEIPT_AI_2_*`, …
(`PROVIDER` = `openai` — любой OpenAI-совместимый `/chat/completions`: Ollama, Mistral, OpenRouter — или `gemini`;
`BASE_URL`, `MODEL`, `API_KEY`, `LOCAL_ADDRESS`, `TIMEOUT_MS` — 60 с по умолчанию, `CONNECT_TIMEOUT_MS` — 2 с,
`CONCURRENCY` — одновременных распознаваний: у адресов в локальной сети по умолчанию 1, у облака без ограничения) пробуются
по порядку. Старые `RECEIPT_AI_*` без номера — слот 1. Следующий слот берётся только при недоступности текущего
(не подключился, таймаут, 5xx/429/401/403, ответ без ожидаемого JSON); «не чек» и «не разобрать» — ответ, дальше не идём.
Повтор при 429/5xx (один, не дольше 20 с паузы) — только у последнего слота. Какой слот распознал чек — в логе
(`Receipt AI slot served`), пользователю не показывается. Схема владельца: Ollama `qwen2.5vl:7b` на ПК с видеокартой
(часто выключен — 2 с на подключение) → облачный ключ, если есть (Gemini через `LOCAL_ADDRESS` в VPN или Mistral) →
Ollama `qwen2.5vl:3b` на самом сервере (медленно, но всегда включена). Запросы — `http(s).request` с `localAddress`.
Ни одного слота — фото получает «распознавание чеков пока не настроено», подсказки в справке и на экране импорта скрыты.

Текст запроса — один шаблон `RECEIPT_PROMPT_TEMPLATE` (`receipt/prompt.js`, заполняет `buildPrompt`): пример ответа в JSON,
формат строки русского чека `НАЗВАНИЕ КОЛ-ВО*ЦЕНА=СУММА НДС X%`, «цифры как напечатано», дата DD.MM.YY. Модели передаются
категории пользователя (как он их видит, вместе с кастомными; у системных — пояснение по-английски `SYSTEM_CATEGORY_HINTS`,
иначе маленькие модели относят продукты к «Покупкам») и основная валюта. Пример категории в образце ответа нейтральный —
конкретную модель копирует во все позиции. Проверено на настоящем чеке «Ярче» (13 позиций) с `qwen2.5vl:3b` на сервере:
все суммы, итог, дата и время, продавец и категории верны, ~80 с. Ответ проверяется
строго (`receipt/normalize.js`): числа строками с запятой, пропущенная сумма = цена × количество, нулевые строки
отбрасываются, отрицательные строки и `discount` — скидка на чек, распределяется пропорционально, если с ней суммы
сходятся с итогом; расхождение с итогом до 1% — позиции подгоняются к итогу (копейки — на самую крупную), больше —
«⚠️ Сверь суммы». До 100 позиций; названия без артикулов и штрихкодов; продавец без «ООО» и кавычек; категория —
по названию из списка пользователя, иначе «Другое»; валюта не из списка бота — «чек в валюте X не поддерживается».
Ничего не разобрано — «сфотографируй ровнее»; не чек — «на фото не чек».

Проверка уверенности: если позиции расходятся с итогом больше чем на 3% или больше чем у 20% строк сумма ≠ количество ×
цена (±1), бот ничего не записывает сам, а показывает черновик (позиции и «не уверен в цифрах — проверь или пришли
более чёткое фото») с кнопками «✅ Записать как есть» (`rvd|1`) и «❌ Отмена» (`rvd|0`). Черновик живёт в памяти 30 минут
(по сообщению; после рестарта — «черновик устарел»), в лимит засчитывается только записанный.

Запись — сразу, одной транзакцией (`ReceiptRepository.create`): чек в `receipts`, по трате на позицию
(`expenses.receipt_id`), описание — название позиции в пределах лимита описания, семья — по режиму «все траты в семью»
(`familyModeTarget`). Дата трат — дата и время чека в поясе пользователя, если не в будущем и не старше 60 дней
(без времени — 12:00, сегодняшний — сейчас), иначе сейчас. Бюджеты проверяются один раз на чек.

| Callback | Описание |
|----------|----------|
| `rv\|<id>\|<page>` | Список чека по текущим данным: `🧾 Продавец · дата · позиций: N · сумма`, позиции по 20 на страницу, кнопки-номера → карточка `ex\|<id>\|r.<id>.<page>` (правка, категория, удаление — обычные; «Назад» и удаление возвращают к списку) |
| `rvok\|<id>` | «Всё верно»: кнопки убираются, остаётся короткая сводка (`status = 'confirmed'`) |
| `rvx\|<id>` → `rvxc\|<id>` | Отменить чек: подтверждение, затем удаляются все оставшиеся траты чека (`status = 'undone'`) |

Лимит — распознанные чеки в локальный календарный месяц (`USER_LIMITS.*.MAX_RECEIPTS_PER_MONTH`: 10 бесплатно, 300 с
премиумом), считаются строки `receipts` (и отменённые); ошибки распознавания не считаются. Сверх лимита — сообщение и
кнопка премиума, нейросеть не вызывается. Лимит `receipt` в `securityMiddleware` — 20 фото за 10 минут (картинки файлом —
лимит `import`). Фото не сохраняются.

│   ├── 🎯 Бюджеты (bg_menu) → Категория (bg_cat) / Карточка (bg|)
│   └── 📄 Итоги (rp|offset)
├── 📅 Сегодня (dy|)
│   ├── ◀️ / ▶️ дни, ‹ › страницы

├── 🔁 Регулярные траты (recurring_menu) → Карточка (rc|)

    ├── 🏦 Накопления (sv) → Обновить остатки (svu), Счёт (svp| → svpc|), Цель (svp| → svgc|), Долг (svb| → svbc|), Добавить (svn), Прогноз (svf), Настройки (svo)

    ├── 📥 Импорт выписки (import) — файл в любой момент → превью (imx|, imgo, imno) → результат → отмена (imu|)
    │   (фото чека — в любой момент → список чека (rv|) → карточки (ex|…|r.) / Всё верно (rvok|) / Отменить (rvx| → rvxc|))
    ├── Настройки (settings)

## Примечания

- Все callback actions обёрнуты в `errorHandler`
- Состояния ввода (доход, регулярная трата, бюджет, семейная трата и др.) хранятся в `StateService` и сбрасываются при нажатии
  любой inline-кнопки (`stateCleanupMiddleware`) или командой `/cancel`; ожидание новой суммы/описания записи живёт до ввода или «Отмена»
- Пользовательский текст (описания, имена семей, username) в сообщениях с `parse_mode: 'Markdown'` экранируется
  `formatter.escapeMarkdown` и не ставится внутрь `*жирного*`: внутри сущности legacy Markdown экранирование не работает
- Локализация: 13 языков, ключ без перевода показывается как есть — новые ключи нужно добавлять во все `src/locales/*.js`.
  Обращение: ru, de, es, fr, pt — на «ты»; tr, ka, kz, uz, hi, jp — вежливое; zh — 你
- Тесты (`npm test`) не ходят в БД: `src/__tests__/setup.js` подменяет `DATABASE_URL` до загрузки модулей
- Эксплуатация (вне репозитория, на сервере):
  - `expenses-bot-backup.timer` (04:30) → `/usr/local/sbin/expenses-bot-backup.sh`: `pg_dump` и `.env` на второй диск
    `/mnt/storage/backups/expenses-bot/`, проверка целостности, хранение 30 дней; при ошибке — сообщение админам в Telegram
  - `expenses-bot-watchdog.timer` (каждые 2 мин) → `/usr/local/sbin/expenses-bot-watchdog.sh`: если у Telegram две проверки
    подряд копятся необработанные обновления (`getWebhookInfo.pending_update_count`), бот перезапускается (не чаще раза
    в 15 минут) и админам приходит сообщение
  - `.github/workflows/bot-watchdog.yml` (GitHub Actions, каждые 10 мин): та же проверка снаружи — на случай, если лежит
    весь сервер или интернет; нужны секреты `BOT_TOKEN` и `ADMIN_CHAT_ID`
